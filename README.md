# 轻卡 · 卡路里记录

一个打开手机浏览器就能用的极简卡路里记录应用：**扫码 / 搜索 / 拍照识别 / 手动输入**食物，按你的基础代谢和目标体重算出每天该吃多少，实时可视化「已摄入」与「还能吃」的热量，以及碳水、蛋白质、脂肪三大营养素进度。

- 纯前端，**0 服务器、0 数据库、0 订阅费**，数据只存在手机本地
- 可「添加到主屏幕」，像 App 一样全屏打开，离线也能记录
- 无需注册、无需审核，改完文件即可用

> 为什么优先做网页（PWA）而不是微信小程序：见文末「关于微信小程序」。

## 功能

| 模块 | 说明 |
| --- | --- |
| 首页 | 热量圆环：还可摄入 / 已超出；已摄入、每日目标、完成度；三大营养素进度条；今日建议；今日饮食 |
| 记录 | 按日期查看，早/午/晚/加餐分组；近 7 天摄入柱状图（含目标线）；点任意记录可改份量、改餐次、删除 |
| 添加食物 | ① 搜索内置 90 种常见食物 ② 扫码查询包装条码 ③ 拍饭菜照片让 AI 估算 ④ 手动填写营养成分表 |
| 我的 | 基础代谢、日常消耗、BMI；目标进度；体重记录；自定义食物库；AI Key 管理；备份导出/导入 |
| 规划 | Mifflin-St Jeor 基础代谢 × 活动系数 → 每日消耗 → 按「每周减/增多少 kg」计算每日热量目标；蛋白质按体重、脂肪按比例、碳水取剩余 |
| 其他 | 离线缓存、深色文字清晰、手机安全区适配、数据备份 |

### 首页

- 圆环中间的大数字 = 每日目标 − 今日已摄入（超出时变红并显示「已超出」）
- 下方三根进度条 = 碳水 / 蛋白质 / 脂肪 的「已吃 / 目标」
- 「今日建议」会自动找出差得最多的营养素，换算成具体食物（例如「蛋白质还差 45 g，约等于 145 g 鸡胸肉」）

### 添加食物的四种方式

1. **搜索**：内置食物库按每 100 g 标注，选中后可输入克数或用「1 碗 / 1 个」等常用份量快捷选择，实时显示换算后的热量与三大营养素。
2. **扫码**：调用手机摄像头识别 EAN/UPC 条码，先查本地自定义食物库，再查免费开放的 [Open Food Facts](https://world.openfoodfacts.org/) 数据库；查到的商品可一键存入「我的食物库」，下次直接搜索。
3. **拍照**：拍一张饭菜照片，AI 估算食物、克数和营养，你改完克数确认后入账。需要自己的 DeepSeek API Key，见下文「AI 拍照识别」。
4. **手动**：按包装上的「营养成分表」填写每 100 g 的热量、碳水、蛋白质、脂肪，可同时保存到食物库。

## 快速开始

### 方式一：本地预览（电脑）

```powershell
cd qingka
python -m http.server 8123
```

浏览器打开 `http://127.0.0.1:8123/`。localhost 属于安全上下文，**电脑上可以直接测试摄像头扫码**。

加上 `?demo=1` 可以看到一份示例数据（不会写入本地存储）：

```
http://127.0.0.1:8123/?demo=1
```

### 方式二：放到手机上用（推荐，免费 HTTPS）

扫码需要 HTTPS（浏览器安全限制），所以推荐用免费静态托管。任选其一：

**A. GitHub Pages（最简单）**

1. 注册 GitHub，新建一个仓库（例如 `qingka`，选 Public）。
2. 把 `qingka/` 目录里的**全部文件**上传到仓库根目录（网页版 Upload files 即可，或 `git push`）。
3. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支选 `main` / 根目录，保存。
4. 等 1–2 分钟，访问 `https://你的用户名.github.io/qingka/`。
5. 手机浏览器打开该网址 → 菜单「添加到主屏幕」。

**B. Cloudflare Pages / Netlify / Vercel**

把整个 `qingka/` 目录拖进它们的网页上传区即可，构建命令留空、输出目录填 `/`，同样免费且自带 HTTPS。

**C. 局域网预览（不推荐用于扫码）**

在电脑上 `python -m http.server 8123`，手机连同一 Wi-Fi 访问 `http://电脑IP:8123/`。
可以正常记录和搜索，但因为是 HTTP，**手机浏览器不允许调用摄像头**，只能手动输入条码。

> 每次修改文件重新上传后，如果手机还显示旧版本，请把 `sw.js` 里的 `CACHE = 'qingka-v1'` 改成 `qingka-v2` 再上传（或在浏览器里清除站点数据）。

### iPhone 使用说明（重点）

- 支持 iOS 15+（建议 iOS 16 或 17）。用 **Safari** 打开网址——iOS 上的 Chrome / Edge 也是 Safari 内核，但「添加到主屏幕」只有 Safari 有。
- Safari 底部 **分享按钮 → 「添加到主屏幕」**，之后从桌面图标全屏打开，没有地址栏，和 App 基本一样。
- **扫码**：必须 HTTPS，首次会弹相机权限。如果主屏幕版打不开相机（iOS 个别版本的限制），有两条路：
  1. 用 Safari 直接打开同一网址扫码，再回桌面版继续用；
  2. 在扫码页点 **「拍照识别」**，对准条码拍一张照片即可——走系统相机，不受网页相机权限影响，识别后自动查营养数据。
- **数据**：保存在本机 Safari。添加到主屏幕后不受 Safari「7 天不访问清缓存」策略影响，但仍建议定期在「我的 → 导出备份」备份。
- **Safari 标签页和主屏幕应用在 iOS 上可能是两套独立的本地存储**（不同 iOS 版本表现不完全一致）。建议固定从主屏幕图标使用；如果两边都用过，先在一边「导出备份」，再到另一边「导入备份」。AI 的 API Key 也要在常用的那一端单独填一次。
- **费用**：不需要 App Store、不需要 Apple 开发者账号（省 688 元/年），也不需要企业签名。

### 安装到主屏幕（通用）

- **iPhone / Safari**：打开网址 → 分享按钮 → 「添加到主屏幕」
- **Android / Chrome**：打开网址 → 右上角菜单 → 「安装应用 / 添加到主屏幕」

安装后全屏运行，没有地址栏，和原生 App 基本一致。

## AI 拍照识别（可选）

拍一张饭菜照片，AI 估算食物、克数和营养，确认后自动入账。默认关闭，需要你自己的 DeepSeek API Key。

### 开启步骤

1. 打开 [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys)，登录后创建 API Key（`sk-` 开头），充值少量金额。
2. 在轻卡里点「我的 → AI 拍照识别 → 填入 API Key」，粘贴并保存。
3. 首页右上角 **＋ → 拍照**，拍一张饭菜照片 →「开始识别」。
4. 结果出来后按实际份量改克数、选餐次 →「全部添加」。

### 费用

模型 `deepseek-flash`，支持图片输入。每张图最多 1024 tokens，一顿约 **$0.0006（约 0.4 分钱）**，一天三顿、一个月通常不到 1 元（按 [官方价格](https://api-docs.deepseek.com/quick_start/pricing) 估算，闲时更便宜）。应用内可设置每日识别上限，默认 20 次/天。

### 隐私与安全

- Key 只保存在你手机浏览器的 localStorage（独立的 `qingka.ai.v1` 键），**不会进入 GitHub 仓库，也不会写进导出的备份文件**。
- 照片在手机端压缩成最长边 1024px 的 JPEG，canvas 重绘会**去掉 EXIF 定位信息**，然后直接发送到 `api.deepseek.com`；本应用没有服务器，也不保存照片。
- 手机丢失或 Key 泄露：到 DeepSeek 后台删除该 Key，或在应用里「Key 设置 → 清除 API Key」。
- 仓库是公开的也没关系：代码里没有 Key，Key 是你在自己手机上手动填的。
- 只拍食物，尽量避开人脸、快递单、证件等敏感信息。

### 准确性

AI 对份量的估算通常有 ±20%–30% 误差，尤其是米饭、面条、酱汁。所以流程是「AI 先填 → 你改克数 → 确认入账」；有包装条码时优先扫码，条码上的数值是精确的。

### 常见报错

| 提示 | 处理 |
| --- | --- |
| API Key 不正确或已失效 | 重新粘贴 Key，注意前后不要带空格 |
| 账户余额不足 | 到 platform.deepseek.com 充值 |
| 请求太频繁 | 等一会儿再试 |
| 今天的识别次数已用完 | 我的 → AI 拍照识别，调高每日上限 |
| 网络连接失败 | 检查手机网络；AI 识别必须联网 |
| 没有识别到食物 | 换一张光线更好、俯拍、能看清全部菜的照片 |

## 计算逻辑

```
基础代谢 BMR（Mifflin-St Jeor）
  男：10×体重kg + 6.25×身高cm − 5×年龄 + 5
  女：10×体重kg + 6.25×身高cm − 5×年龄 − 161

每日消耗 TDEE = BMR × 活动系数（1.2 / 1.375 / 1.55 / 1.725 / 1.9）

每日热量目标
  减脂：TDEE − 每周目标kg × 7700 ÷ 7
  增重：TDEE + 每周目标kg × 7700 ÷ 7
  维持：TDEE
  保护：女性不低于 1200、男性不低于 1500 千卡；单日缺口不超过 TDEE 的 30%

三大营养素
  蛋白质 = 蛋白质系数(1.2/1.6/2.0 g/kg) × 体重（减脂时用目标体重）
  脂肪   = 每日目标 × 脂肪占比(20/25/30/35%) ÷ 9
  碳水   = (每日目标 − 蛋白质×4 − 脂肪×9) ÷ 4
```

体重记录会同步更新当前体重，从而自动修正后续的热量目标；「我的」页会按当前速度预估到达目标体重的日期。

食物营养值为常见参考值（中国食物成分表 / USDA / 包装标示），**仅供估算**，不是医疗或营养处方。

## 数据与隐私

- 所有资料、饮食记录、体重、自定义食物都保存在浏览器 `localStorage`，不上传任何服务器。
- 换手机 / 清缓存前，请在「我的 → 导出备份」保存 JSON；新设备「导入备份」即可恢复。
- 清除浏览器站点数据会丢失记录，请定期备份。
- 条码查询会把你扫描的条码发给 Open Food Facts（仅条码，不含个人信息）。
- 启用 AI 拍照识别后：Key 存在本机独立键里（不进入备份），照片只会发送给 DeepSeek 用于识别，不会上传到本应用（本应用没有服务器）。

## 文件结构

```
qingka/
├── index.html              # 页面骨架、底部标签栏
├── styles.css              # 全部样式（移动优先）
├── manifest.webmanifest    # PWA 清单
├── sw.js                   # Service Worker：离线缓存
├── js/
│   ├── nutrition.js        # 纯计算：BMR/TDEE/热量目标/宏量/目标日期
│   ├── foods.js            # 内置食物库（90 种，每 100g）
│   ├── state.js            # localStorage 读写
│   ├── ui.js               # 弹层、提示、图标、格式化
│   ├── scanner.js          # 摄像头 + ZXing 扫码
│   ├── off.js              # Open Food Facts 条码查询
│   ├── ai.js               # AI 拍照识别（DeepSeek 视觉 API、Key 管理、图片压缩）
│   ├── pwa.js              # 注册 Service Worker
│   └── app.js              # 路由、各页面渲染、交互
├── vendor/zxing.min.js     # 扫码引擎
├── icons/                  # 应用图标
├── tests/                  # 计算与界面自动化测试
└── tools/make_icons.py     # 重新生成图标
```

### 想改点什么

- **加食物**：编辑 `js/foods.js`，照现有格式加一行（`kcal/carb/protein/fat` 为每 100 g，`portion` 为常用份量）。
- **改配色**：`styles.css` 顶部的 `:root` 变量（`--accent` 主色、三大营养素颜色）。
- **改名称**：`index.html` 的 `<title>`、页面里的「轻卡」、`manifest.webmanifest` 的 `name`。
- **换条码数据源**：只改 `js/off.js` 里的 `lookup()`，返回 `{ name, per100:{kcal,carb,protein,fat} }` 即可。
- **换 AI 模型**：`js/ai.js` 顶部的 `MODEL` 和 `API_URL`；只要接口是 OpenAI 兼容格式、支持图片输入即可。

## 关于微信小程序

如果最终一定要上微信小程序，本项目的前端逻辑（计算、食物库、交互）可以直接复用，但要额外付出这些成本：

| 项目 | 说明 |
| --- | --- |
| 账号 | 个人主体可免费注册，需实名 |
| 服务器域名 | 小程序请求的 HTTPS 域名需要 **ICP 备案**（个人备案可行，但需要域名 + 时间） |
| 扫码 | `wx.scanCode()` 可调用微信扫码，无需自己接相机，体验比网页更好 |
| AI 识图 | 需要把 DeepSeek Key 放服务端（云函数），不能像网页这样放在本机 |
| 审核 | 每次发版需要审核；食品/健康类内容可能被要求补充资质说明 |
| 数据 | 可存 `wx.setStorageSync` 本地，或接微信云开发（有免费额度） |

也就是说：**做一个小程序不难，难在域名备案和审核**。如果你的核心诉求是「自己随时随地能用、成本尽量低」，PWA 已经能 100% 满足，且今天就能用。若你需要把链接分享给朋友、在微信里直接打开，网页版同样可以。
